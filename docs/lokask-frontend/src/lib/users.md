### 📚 Overview

This module serves as a centralized client-side service layer for making common asynchronous API calls. Its primary function is to abstract the direct fetching logic (`fetchJson`) and provide type-safe wrappers for critical functionalities, specifically:

1.  Fetching standardized reference data (e.g., city lists).
2.  Handling complex file uploads (e.g., user avatars).

By centralizing these interactions, we improve code maintainability, enforce consistent error handling, and ensure that endpoint definitions are managed in one place.

#### 🚀 API Functions

##### 1. `getCities(): Promise<CityOption[]>`

*   **Endpoint:** `/cities`
*   **Method:** GET
*   **Description:** Retrieves a list of available city options, which are typically used for dropdown selections across various forms (e.g., registration, search).
*   **Flow:** Calls `fetchJson` with no parameters, expecting an array of `CityOption` objects.

##### 2. `uploadAvatar(file: File): Promise<any>`

*   **Endpoint:** `/users/avatar`
*   **Method:** POST
*   **Description:** Handles the multi-part form data submission required to upload a user's profile picture (avatar).
*   **Process:**
    1.  A `FormData` object is instantiated.
    2.  The input `File` object is appended under the key `"avatar"`.
    3.  `fetchJson` is called with the `POST` method and the `FormData` body.

### 📝 Notes & Best Practices

1.  **File Input Validation:** Before calling `uploadAvatar`, always validate the input `File` object to ensure it meets size and type constraints (e.g., checking the MIME type for an image). Do not rely solely on backend validation.
2.  **Data Immutability:** This service layer should be used purely for data retrieval. Any state mutations triggered by successful API calls must be handled by dedicated state management slices (e.g., using dispatch functions).
3.  **Code Structure:** Consider separating file upload logic into a dedicated `file-storage.ts` module if the project grows to include more types of uploads (e.g., document uploads, large media assets).
